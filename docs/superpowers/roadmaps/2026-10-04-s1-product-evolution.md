# S1 产品演进路线与后续设计任务

Date: 2026-10-04, Asia/Shanghai.
Status: 产品路线草案，供操作员审阅；不修改已批准 spec 或当前实施计划。
Authority: 操作员要求在 Cursor 实施期间，由 Codex 明确后续几轮产品方向与设计。
Roles: Codex 负责方向、设计、验收定义和独立审阅；Cursor 负责另行授权的实现与验证。

## 1. 持续目标与轮次含义

目标是让能重复运行音频脚本或 DSP 处理链的开发者，完成有证据的版本排障、复测与修复核查。单文件诊断保留为入口；产品不把单文件等同于长期能力上限。

本路线按四轮产品能力组织。每轮可以包含多个实现 PR。第一轮现有计划的 A/B/C 都属于第一轮，不能把技术分段误算成产品轮次。

前一轮实现与后一轮设计可以并行。后一轮不能在前一轮尚未确定的接口、测量能力或实验结果上建立假设事实。

本文件确定推荐顺序、每轮要回答的问题、最小范围与进入条件。具体数值、接口和实施授权仍以该轮审阅通过的 spec/plan 为准。没有依据的参数不提前冻结。

## 2. 四轮产品路线

| 轮次 | 用户承诺 | 最小增量 | 完成时必须看到的证据 |
|---|---|---|---|
| R1 比较与复测工作台 | 我能提交两版输出，看懂变化，并组织一次复测 | 已批准 spec 的比较准入、记录、当前会话案例、Web、导出与独立建议接口 | 真实离线输入贯通，来源不串侧，不适用和失败不假通过 |
| R2 可用的回归规则与有效复测 | 我知道哪些变化超过了这个测试条件下允许的范围，以及下一次测试是否有帮助 | 有限产品比较规则、获验证的复测参数、真实模型及任务收益验证 | 至少一项有适用范围的规则获得独立验证，复测有效性与 planner 收益分开报告 |
| R3 有界多故障与定位 | 我能找到问题发生的区间，并区分更多相邻现象 | 首选持续周期输入中的短时掉音；其次根据案例决定直流偏移，结合现有 clipping/harmonic | 区间定位、混合现象、正常瞬态和开始/结束边界的反例通过，用户行动实际改变 |
| R4 可重复使用的排障流程 | 我能再次打开案例，并用相同设置检查多个版本或输入 | 案例保存/恢复、复用测试条件、小批量检查与版本历史，按真实使用需要选定子集 | 重启恢复与证据一致性可靠，重复任务确实减少人工操作，失败不会污染已有结果 |

R2 的证据决定 R3 的正式范围。R3 不以“故障数达到某个数字”为成功条件。R4 的投入取决于重复使用证据，不默认扩为通用 CI 平台。

R2/R3 的新需求不得直接塞进 Cursor 当前 diff。影响 R1 设计时，由 Codex 单独提出兼容性或设计修订，交操作员决定。

## 4. R2 设计任务：使比较与复测具备实际判定价值

### 4.1 主问题和三种路径

| 路径 | 价值 | 决定 |
|---|---|---|
| 先扩大模型运行量 | 能观察更多建议 | 不能补齐科学容差，暂不作为先手 |
| 先做有限规则与复测参数验证，再评估 planner | 区分测量能力、规则正确性和模型增量 | 推荐 |
| 先新增故障算法 | 增加可检测现象 | 会同时扩大未验证规则人口，放在 R3 |

R2 分成两个可以分别验收的设计包，不要求先完成一场大型战役才让产品可用。

第一包是确定性规则与复测资格。第二包是真实模型和用户任务验证。第二包不能倒过来用“模型看起来有道理”批准第一包的阈值。

### 4.2 规则与复测资格设计包

初始对象仍为 clipping_ratio 与有资格条件的 THD 比较。优先验证数据能支持的最少检查项，不预承诺两项都可启用。

每个拟启用规则明确：

- 输入信号族、处理链可重复性前提、通道及分析范围。
- 测量算法和配置身份、指标单位、允许变化方向及数值容差。
- 校准材料与独立验证材料的划分。相同处理链、原始刺激及其变体按来源分组，避免仅改文件名就跨组。
- 正常变化、已知回归、不适用输入及现有异常仍然存在的案例。
- 误报、漏报、拒绝比较和覆盖率的分母；不得排除困难案例后宣称通过。

规则数值通过离线测量校准并审阅，不能由 LLM 生成，不能沿用 demo 诊断阈值。没有证据支持 THD 基频兼容范围时，该项仍被阻断，削波项目可以单独推进。

降低输入电平的复测方案单独确定适用条件、变化幅度、保持项和解释范围。两版本使用相同的新输入，不能对输出事后归一化。检查幅度变化导致的噪声或量化影响，不能把更小信号自动当作更好结果。

没有受支持的处理链执行设施时，用户在自己的程序中生成复测输出；Codex/产品不自动执行用户代码。离线夹具与经授权的 Cursor 测试可以验证参数行为，但不能充当用户真实使用记录。

该包的设计产物是有限规则候选、方案资格表、校准/验证数据清单和规则审阅标准。正式数值与通过线在查看独立验证结果前批准。

### 4.3 模型与任务收益设计包

首先分别衡量：

1. 工作台相对现有报告/手工检查是否帮助用户完成排障。
2. Planner 相对固定复测策略是否有额外收益。

不把第一项收益自动归因于 LLM。固定策略和模型使用相同初始测量、方案目录与预算。

模型侧记录合法建议率、无效建议、正确 abstain、复测区分效果、调用成本和共同边界下的时延。用户侧记录完成任务所需时间、复测次数、错误操作及完成情况。

允许三个结果：planner 有增量、当前未显示增量、证据不足。不能事后把任何结果都写成 agent 获胜。固定策略更好时，提出新的产品角色设计，不静默替换现行 RealLLMPlanner。

研究数字、真实模型预算及运行授权另行审批。R1 的 fake transport 验收不计入真实模型结果；少量演示不能写成质量认证。

### 4.4 现在可做与必须等待的部分

现在可设计规则候选的证据要求、数据分组、判定人口、评分定义和失败案例，完全不依赖 Cursor 已完成代码。

需要 R1 输出后核定实际测量配置、字段接口、误差表现、计时起止点及代码身份；数值容差和调用预算不能先猜。设计冻结前核对实际样本取得条件，不能为凑样本虚构用户或真实案例。

R2 可在有限规则通过审阅后发布相应能力，未通过的项目继续显示未覆盖。不要求为了产品发布而证明所有 planner 优势。

## 5. R3 设计任务：多故障能力与事件定位

推荐首先研究持续周期输入中的短时掉音。用户结果是指出发生区间、受影响通道、相对基准变化和是否复现，帮助检查处理链中断。

这是下一轮候选功能，不是已有检测能力或已验证最优算法。首期用可控注入和相同输入的输出对比建立真值，再补实际案例。已知静音段、启动/结束段、正常包络变化与自然瞬态必须作反例。

检测到能量缺口只能说明局部现象，不直接确认缓冲区 underrun、设备故障或某个代码位置。需要其它证据才能提升根因结论。

直流偏移作为第二候选：只有真实排障案例需要，并能定义合理窗口、单位、参考条件和容差时才进入。符号与绝对量分开记录，不能用声道混合掩盖相反偏移。

设计须覆盖现有削波与新增现象同时出现的情况。例如，不能因已发现削波而跳过独立掉音，也不能把所有频谱变化合并解释为谐波失真。每种结论保留独立证据和适用条件。

采用条件：事件定位和新增检测至少解决一类 R2 案例中无法有效处理的任务。若新增类别不改变用户行动，则保留研究结果，不强行加入产品。

后续 artifact 为一份有界扩域 spec，包括事件区间的数据形状、测量定义、区间评价方法、混合现象规则、交互定位方案与错误归因约束。具体算法与阈值等真实样本和前轮结果后选择。

## 6. R4 设计任务：重复使用与案例连续性

优先解决 R1 当前会话结束就无法继续的限制，再考虑小批量检查。持久化不是本轮授权，其数据生命周期需要独立设计。

候选顺序：

1. 保存并重新打开案例，校验输入、结果、规则和代码身份。
2. 复用已经明确的测试条件，用户确认版本与文件映射后再次检查。
3. 对少量输入和版本执行有界批次，汇总覆盖、失败和变化。
4. 确有使用需求时提供 CI 输出或外部处理程序适配。

同一案例重新打开时不得拿当前规则覆盖旧判定。重新评分创建新记录，并显示它与原结果的规则差异。旧文件缺失、hash 不一致或 schema 不支持时明确拒绝恢复受影响能力。

批处理必须有并发、内存、取消和失败隔离。一个输入失败不改变另一输入的旧结果，也不能从总体通过分母中消失。

采用条件是用户确实重复执行相同任务或需要跨会话排障。若使用停留在一次性演示，先改善案例取得与任务适配，不为展示架构增加数据库或分布式执行。

## 7. 知识检索、多 Agent 与自动执行的引入条件

这些是按需架构选项，不是排定的第五轮必做项目。

| 选项 | 需要的前置证据 | 接受前必须验证 |
|---|---|---|
| 结构化知识与语义检索 | 设备/处理参数资料增长，用户术语与资料术语不一致造成可复现漏检 | 同一语料与查询下优于现有检索；来源、版本和无答案处理可靠 |
| 多 Agent | 信号分析、资料核对或测试条件调查确实可独立开展 | 相同任务和预算下，质量、覆盖或耗时收益超过协调成本 |
| 插件或处理链自动执行 | 用户反复手动生成输出成为主要成本 | 明确执行边界、资源限制、参数记录和结果可复现性 |
| 泛化到任意音频 | 周期信号以外的真实任务有足够验证材料 | 内容合法变化与异常可区分，新域单独定义合同与评价 |

Scope gates 要求新设计与授权，不是永久禁止扩展。RAG 只能补知识，不能制造信号 Evidence。多个 Agent 也不能替代未取得的参考或实验条件。

## 8. Codex 与 Cursor 并行协作

Cursor 当前按其获得的 R1 阶段授权实施。Codex 在独立文档中设计 R2，不修改正在实施的 spec、接口或测试 ID。R3/R4 先保留本路线中的目标与条件，避免在实现结果未知时写大量精确接口。

R1 每个交付完成后，Codex核对其实现证据。R2 设计只有在真实接口和测量前提已核实时，才转成可交付实施计划。发现跨轮设计冲突时，先记录冲突和最小调整，不要求 Cursor 隐式返工。

交给 Cursor 的每轮材料必须包含完整 spec、plan、确定的基线、前置结果和明确阶段授权。不能只给本机文件路径、SHA 前缀或一句“按路线继续”。

路线确认不授权给其它会话发消息、不创建后台任务，也不授权 commit/push/merge、seal 或 RealLLM。持续工作仅发生在当前已授权的设计范围内。

## 9. 当前推荐决策

保持四轮推荐顺序。当前并行设计的重点是 R2 的第一包：比较规则与复测资格；同时准备第二包的评价定义。R3 明确扩域优先级，R4 明确重复使用目标，不提前冻结接口或技术组件。

不以固定日历承诺每轮时间。R1 接口稳定、样本可得性和验证结果决定后续工作量。某轮未证明收益时，可以缩小范围或改变顺序，不能以完成路线表为理由继续增加功能。
