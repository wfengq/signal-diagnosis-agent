# 基频估计修复：次谐波锁定与整数延迟分辨率（设计草案）

日期：2026-10-06
状态：操作员 2026-10-06 批准（范围 A；八度歧义检测本次不修，记为 OQ-024）。§7 的冲突由操作员选 B 解决（2026-10-06），实现见 §8。
上位依据：AGENTS.md（Scope gates、Preserved evidence）、`docs/ARCHITECTURE_V0_2.md`（`dsp/` 只放确定性算法）、`docs/CONTRACTS_V0_2.md`（冻结 §§1–64）、`CONTRACTS_V0_3_CONTEXTUAL.md`、D045 与增量研究报告。

## 1. 问题

`dsp/pitch.py` 的 `estimate_f0_autocorrelation` 在 [fs/1000, fs/50] 的延迟范围内取归一化自相关的**全局最大值**，并且只取整数延迟。两个缺陷由此而来。

### 1.1 次谐波锁定（错误的频率）

周期不是整数个采样点时，第 1 个周期处的自相关峰会略低于第 k 个周期处的峰；后者的 k 倍周期恰好更接近整数，于是被选中，估出 f0/k。

实测（纯正弦，1 秒，2026-10-06）：

| 采样率 | 真实频率 | 现在的估计 | 说明 |
|---|---|---|---|
| 8 kHz | 440 Hz | 87.91 Hz | 选中延迟 91（≈5 个周期，90.9） |
| 16 kHz | 440 Hz | 146.79 Hz | 3 个周期 |
| 8 kHz | 220 Hz | 73.39 Hz | 3 个周期 |
| 48 kHz | 440 Hz | 440.37 Hz | 正确 |

8 kHz、440 Hz 时，延迟 18 的自相关为 0.99799，延迟 91 为 0.99866。现有的八度歧义检测（`detect_octave_ambiguity`）在这些例子里都没有报警。

后果：谐波分析以错误的基频为准，谐波次数和 THD 全部错位。这不只影响研究：

- 增量研究 T2 的 6 道谐波题，任何一组都答不出；
- 产品单文件路径在 8/16 kHz 常见采样率下受影响；
- 仓库里已有一个专门的探针用例 `v03dev_3a0c28…`，标注就是“700 Hz subharmonic-lock probe”，估出 350.4 Hz；
- 已封存的外部 WAV 参考摘要里，`30ae08…` 估出 350.4 Hz，THD 因此是荒谬的约 3,471,458 %。

### 1.2 整数延迟分辨率（不准的频率）

只取整数延迟，误差约为 f0²/fs。例如：

- 44.1 kHz、1000 Hz 估成 1002.27 Hz；
- 修好次谐波后，8 kHz、440 Hz 会估成 444.44 Hz（延迟 18）。

## 2. 改动

只改 `dsp/pitch.py` 的峰值选择，不改函数签名和 `F0Estimate` 字段。

1. **最短延迟优先（修 1.1）：** 在搜索范围内找所有局部极大值，取自相关值不低于全局最大值减去容差 `subharmonic_tolerance` 的**最短**延迟。容差是带版本的 DSP 参数，默认 0.01，作为关键字参数暴露，与现有 `octave_ambiguity_tolerance` 同类。它是算法参数，不是规则阈值。
2. **抛物线插值（修 1.2）：** 对选中的峰用相邻三点做抛物线插值，得到亚采样精度的延迟，`f0 = fs / 插值延迟`。
3. `method` 字段保持 `"autocorrelation"`：冻结的 V0.2 测试 T039/T040 钉住了这个值。算法版本由新决策和身份记录区分。
4. 置信度、清浊判断、八度歧义检测和 `fundamental_relative_energy` 的调用方式不变，只是改在新的延迟上计算。

## 3. 影响面（已实测）

对仓库里全部 320 个信号比较新旧估计：72 个 V0.2 合成用例，加上 `docs/evaluations` 下所有 WAV。

**只做第 1 项（最短延迟优先）：**
- V0.2 合成用例：**0 个变化**，容差取 0.002–0.02 结果相同；
- WAV：25 个变化，均为次谐波锁定被纠正或无基频信号：
  - 增量研究 T2 谐波用例：12 个，87.9 Hz → 444.4 Hz；
  - 外部 WAV 700 Hz 正弦：9 个，350.4 Hz → 695.7 Hz；
  - V0.3 开发集探针：2 个，440 Hz 加噪声和 700 Hz 探针；
  - 狗叫声：2 个（同一段录音，在两个开发集目录各一份），本无基频，预期结论为 `inconclusive`，484.6 Hz → 723.0 Hz。

**加上第 2 项（抛物线插值）：**
- 上述纠正后的值变准：444.4 → 440.04 Hz，695.7 → 700.0 Hz，1002.27 → 1000.004 Hz；
- **但每个 V0.2 合成用例的估计都会移动**：63 个有声用例，最大偏移 0.17%，相对真值的最大误差从 0.175% 降到 0.0025%。

## 7. 实现中发现的冲突（2026-10-06，实现已暂停）

按批准的范围 A 实现后，离线结果如下。

**已达到的：**
- V0.2 的 72 个用例：规则判定逐例不变，基频估计最大偏移 0.175%。
- 有 5 个已失真的 V0.2 用例，THD 读数变化较大，但判定都仍是 FAIL。新读数与“在真实基频处精确取谐波”的真值完全一致；旧读数偏低，最多低了一半：
  - `case_v11_held_combined_01`：9.29% → 18.65%；
  - `case_v12_held_clipping_04`：5.60% → 11.63%。

  原因是旧估计偏了约 0.4 Hz，第 5 次谐波因此偏离约 4 个频率格。
- 探针 WAV 和 T2 谐波用例都估对了。

**冲突：** V0.3 Workstream A 的既定规格 `docs/evaluations/v0_3/prerequisites/octave_ambiguity_spec.md` 把“不重新选择 F0”列为非目标（“No F0 re-selection”）。下列 4 个既有测试正是用“700 Hz 纯音锁在 350 Hz”这个现象作夹具，来测试可靠性门槛和八度歧义标记：

| 测试 | 断言 |
|---|---|
| T-A-002 | 估计保持 ≈350 Hz，并标记八度歧义 |
| T-A-004 | `f0_reliability` 为 `unreliable` |
| T-B-001 | 谐波分析无效，原因为基频格能量不足 |
| T-B-004 | 同上，校验原因字符串 |

修复后不再锁定，这 4 个测试失败。改动它们需要你授权，因此实现停在这里。

**另外两个未完成项（实现细节）：**
- 8 kHz、700 Hz 仍锁在 350 Hz：整数延迟处的峰高被低估，单靠 0.01 的容差不够。需要先插值再比较峰高。
- T-CX431 的测试代码有一处调用写错，需要改。

**可选方案：**
- **A. 按原设计改默认行为。** 在 D049 中声明取代 Workstream A 的“不重新选择 F0”这一非目标，并为 4 个测试换夹具，保留它们的本意：
  - 门槛类测试（T-A-004、T-B-001、T-B-004）改用“缺失基频”的信号，例如只有 700 Hz 和 1050 Hz 两个分量。它的周期对应 350 Hz，而 350 Hz 处没有能量，所以仍会触发同一个门槛；
  - T-A-002 改为直接对 `detect_octave_ambiguity` 做单元测试。
  - 代价：要修改既有测试的夹具，需要你授权。
- **B（推荐）. 新行为改为调用方显式开启。** `estimate_f0_autocorrelation` 和 `analyze_harmonic_distortion` 增加关键字参数 `subharmonic_guard`，默认关闭，保持旧行为；产品的工具层（`tools/service.py`）显式开启。
  - 好处：既有测试和 Workstream A 规格一字不动，产品照样得到修复，T-CX428–T-CX432 改为测开启后的路径。
  - 代价：`dsp` 默认行为仍保留旧缺陷，直接调用者要自己开启。

## 8. 按方案 B 的实现（2026-10-06）

- **`dsp/pitch.py`：**
  - `estimate_f0_autocorrelation` 新增 `subharmonic_guard`（默认 `None`，即关闭；关闭时与旧估计逐字节一致）和 `subharmonic_tolerance`（0.01）。
  - 开启后，在所有局部峰中，按抛物线插值后的峰高，取不低于最高峰减容差的最短延迟，再用插值位置算频率。
  - 比较插值后的峰高，才能修好 8 kHz、700 Hz：整数延迟处的峰高会被低估。
- **`dsp/harmonics.py`：** 把开关透传给基频估计。
- **开关的作用范围：** 用 `subharmonic_guard_enabled()` 设定，嵌套的调用也生效，例如 `dsp/contextual.py` 内部的谐波分析。
- **`tools/guarded_service.py`（新文件）：** `GuardedSignalToolService` 在开关打开的范围内运行三个依赖基频的工具。
  - 原 `tools/service.py` 是 D043 起冻结的文件（T-CX351），因此不改它。
- **产品接线：** `app/service.py` 的两条运行路径改用 `GuardedSignalToolService`。规划器消融适配器中的固定流程组也改用它，否则产品组与固定流程组的工具不一致，T-CX293 的对齐断言会失败。
- **保持旧估计的地方：** 评测运行器、已记录的研究、回归工作台、数据集校验，继续用旧估计，以保证已记录结果可复现。
- **测试：** 新增 T-CX433，固定上述接线范围。T-A-002、T-A-004、T-B-001、T-B-004 与 Workstream A 规格不改，全部通过。
