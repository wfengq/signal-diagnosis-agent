# 参考对比模式的故障时间定位（设计草案）

日期：2026-10-07
状态：草案，待操作员审批。本文件不授权实现，也不授权任何真实模型运行。
上位依据：AGENTS.md（Scope gates）、`docs/CONTRACTS_V0_3_CONTEXTUAL.md` §17、§24.2、§26、§27，D037、D049、D050。

## 1. 为什么做

D050 让产品报告故障出现的时间和声道，但参考对比（`paired_reference`）模式只定位削波。用户上传了参考文件，谐波失真却只有整文件的结论，不知道出现在哪一段。

这一项把参考对比模式补齐：逐段比较待测和参考，定位“待测比参考多出来的谐波”出现在哪里。

## 2. 目标与非目标

**目标：** 参考对比模式的运行结束后，故障位置里除了削波，也能给出谐波失真的区间，每个区间引用同一次运行中的分段 Evidence 和规则判定。

**非目标：**
- 不改诊断 planner（仍为 v9.11）、prompt 和 agent 的结论；
- 不新增规则或阈值，不调用模型；
- 不改冻结的 `tools/`、`dsp/harmonics.py`、`dsp/contextual.py`；
- 不改单文件和声明单音模式现有的扫描（D050 不变）。

## 3. 做法

### 3.1 每个窗口怎么比

沿用 D050 的窗口（0.25 秒）和声道（单声道扫 mixdown，立体声扫 left、right、mixdown）。

参考对比模式下，每个窗口用同一个时间范围调用现有工具 `analyze_contextual_distortion`（经 D049 的 `GuardedSignalToolService`）。工具对两段同时截取，在窗口内部做对齐，再比较各次谐波的增长。工具和 DSP 代码都不改。

离线实验（合成音符，在 1.0–1.5 秒注入偶次谐波失真，固定参数，无随机）：

| 待测相对参考的时间偏移 | 结果 |
|---|---|
| 0、3、30 毫秒 | 增长只出现在 1.00 和 1.25 秒开始的窗口，其余窗口为 0 |
| 200 毫秒 | 增长出现在 1.25 和 1.50 秒开始的窗口，正好是待测文件里失真所在的时间；开头被补零的窗口判为不可比较 |

结论：位置按待测文件的时间轴报告；稳态参考下，几十毫秒的偏移不影响定位；衰减音符上也成立。

### 3.2 判定

用产品已在使用的情境规则版本 `profile_s1_contextual_comparison_v9_10`（阈值为现有演示值，不改）。一个窗口支持“谐波失真”的条件与产品整文件判定相同：

- `rule_contextual_analysis_valid` PASS；
- `rule_contextual_f0_compatible` PASS；
- `rule_reference_clipping_ratio_acceptable` PASS；
- `rule_reference_flat_top_absent` PASS；
- `rule_even_harmonic_growth_acceptable` FAIL。

前四条有任何一条不通过，该窗口记为“不可比较”，不支持任何故障，报告里给出不可比较窗口的数量。

削波仍按 D050：用 `detect_clipping` 和 `profile_s1_segment_evidence` 扫待测文件。

合并、`agrees_with_diagnosis`、“需要复核”的标注都与 D050 相同。

### 3.3 输出

`fault_localization` 的形状基本不变：
- `harmonic_scanned` 在参考对比模式下为 true；
- 新增 `harmonic_basis`：`nominal_thd`（声明单音）或 `reference_growth`（参考对比），未扫谐波时不出现；
- 新增 `windows_not_comparable`：参考对比模式下不可比较的窗口数，其他模式不出现。

扫描版本升为 `product-segment-scan-1.1`。单文件和声明单音模式的结果与 1.0 相同，只有版本号变化。

页面、HTML 报告和 CLI 的说明文字按 `harmonic_basis` 显示，例如“已逐段与参考比较谐波增长”。

### 3.4 代价

每个窗口要做对齐和四次谐波分析，比 D050 慢。实测（48 kHz）：

| 文件 | 50% 重叠 | 不重叠 |
|---|---|---|
| 30 秒立体声（3 个声道） | 约 13 秒 | 约 6.3 秒 |
| 5 秒单声道 | 约 0.6 秒 | 约 0.3 秒 |

扫描完成之前，运行不会显示“已完成”，所以长文件的等待时间会直接被用户感受到。见 §6 决策 1。

## 6. 待操作员决定

1. **扫描密度：**
   - A（推荐）：参考对比模式用不重叠的 0.25 秒窗口。耗时减半，定位精度仍是 0.25 秒；其他模式保持 50% 重叠。
   - B：和其他模式一样 50% 重叠，30 秒立体声约 13 秒。
   - C：先只扫 mixdown，再对有问题的窗口补扫左右声道。最快，但只有一个声道失真时，mixdown 里的增长会被稀释，可能漏报。
2. **不可比较的窗口：**
   - A（推荐）：只报告数量，不展示位置。
   - B：同时列出不可比较的时间段，便于检查对齐或静音问题。
3. **真实数据：** 实现完成后，用 EGFxSet（CC BY 4.0，真实硬件效果器处理的吉他音符，自带干净参考）抽样几十个文件做离线检查。需要操作员在环境网络设置里放行 `zenodo.org`。音频不进仓库，只提交文件清单、校验值和下载脚本。
   - A（推荐）：同意，作为 D051 的验证附录单独提交。
   - B：暂不做。
