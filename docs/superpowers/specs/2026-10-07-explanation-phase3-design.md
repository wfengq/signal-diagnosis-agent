# D052 第 3 阶段：解释层（设计）

日期：2026-10-07
状态：已批准（操作员 2026-10-07，§9 四项均选 A；D055）。授权按本设计实现离线部分；真实模型评测交给 Cursor 运行。
上位依据：D052、D053、D054、`docs/superpowers/specs/2026-10-07-route-adjustment-device-testing-design.md` §5 阶段 3、AGENTS.md。

## 1. 要解决什么

现在的诊断结论是对的，但难读：

- 情境诊断（D053 引擎）的报告给出结论、证据编号、规则编号和阈值，用户要自己把它们拼成“发生了什么”；
- 扫频测试（D054）给出每个频段的 THD、主要阶次和规则判定，用户要自己看出“从哪个音量、哪个频段开始超标，意味着什么”；
- 两者都没有告诉用户“下一步该做什么”。

这一阶段加一个解释层：把同一次运行的结论、证据和规则判定讲成人话，并给出下一步建议。

**解释层不改变结论。** 结论仍然只来自确定性引擎和版本化规则。解释层读结论，不写结论；它说的每句话都要引用同一次运行的编号，提到的每个数字都要和证据一致。做不到就拒绝模型的输出，改用确定性模板。这里的回退是“回退到模板”，不是回退到桩 planner（AGENTS.md）。

## 2. 输入：解释材料包（确定性生成）

解释层只看到一个紧凑的“材料包”，由运行结果确定性地生成，不含波形、频谱或文件内容：

| 来源 | 材料包里的内容 |
|---|---|
| 运行身份 | 运行编号、模式（单文件 / 参考对比 / 标称单音 / 扫频）、引擎版本、规则档案版本 |
| 结论 | 每个结论的编号、故障类型、确定性陈述 |
| 证据 / 事实 | 被结论或判定引用的那些条目：编号、指标名、数值、单位、**显示字符串**（如 `6.70%`、`-6 dB`、`125 Hz`） |
| 规则判定 | 编号、规则名、角色、实测值、比较符、阈值（标为“演示阈值”）、判定结果 |
| 定位（若有） | 情境诊断的时间区间（D050/D051），扫频的频段与起始电平 |
| 知识 | 引擎已检索的知识片段（`knowledge/corpus`），只作解释用 |
| 下一步菜单 | 确定性计算出的“可选下一步”（§4），每项带编号和触发它的判定编号 |

材料包有版本号（`explain-packet-1.0`）和 SHA-256 摘要，写进解释结果，便于复现。

## 3. 输出：分段解释

模型只返回一个 JSON 对象：

```json
{
  "sections": [
    {"kind": "conclusion", "sentences": [{"text": "...", "refs": ["claim_..."]}]},
    {"kind": "evidence",   "sentences": [{"text": "...", "refs": ["ev_...", "rule_eval_..."]}]},
    {"kind": "meaning",    "sentences": [{"text": "...", "refs": ["claim_...", "chunk_..."]}]},
    {"kind": "next_steps", "steps": [{"step_id": "lower_playback_level", "text": "...", "refs": ["rule_eval_..."]}]}
  ]
}
```

- 四个段落固定顺序：**结论**、**依据**、**含义**、**下一步**；
- 默认中文，可选英文（跟随页面语言）；
- 每段最多 4 句，每句最多 120 字，总长有上限。

## 4. 下一步：只能从确定性菜单里选

下一步建议的风险最大：模型容易“建议”出产品没有依据的操作。因此下一步菜单由代码确定性地算出，模型只能从中选择并改写措辞（这和回归工作台的复测建议 `v0.3-s1-retest-1.0` 是同一种做法）。

示例（实现时以规则判定为准，最终清单写进合同）：

| 下一步编号 | 何时可选（由判定决定） |
|---|---|
| `lower_playback_level` | 认定削波，或扫频起始电平存在 |
| `check_recorder_gain` | 录音达到满刻度（扫频满刻度规则不通过） |
| `add_reference_recording` | 单文件模式，谐波按 D037 不认定 |
| `state_nominal_tone` | 单文件模式，信号像单音但未声明频率 |
| `run_sweep_test` | 情境诊断无法下结论，或只能在单文件模式下怀疑谐波 |
| `add_sweep_levels` | 扫频只测了一个音量且发现失真，想找起始电平 |
| `rerecord_quieter` | 扫频信噪比规则不通过，或频段不可测 |
| `check_stimulus_file` | 扫频对齐规则不通过 |
| `use_one_clock` | 扫频时钟漂移规则不通过 |
| `record_whole_stimulus` | 录音被截断 |

如果菜单为空（例如没有故障、各项都通过），下一步段落可以为空。

## 5. 校验（确定性，失败即拒绝）

模型输出必须全部通过以下检查，任何一项不通过，整份解释作废，改用模板（§6）：

1. **结构：** JSON 能解析，字段和段落顺序符合 §3，长度在上限内。
2. **引用：** 每句至少引用一个编号，所有编号都在材料包里。结论段必须引用本次运行的每一个结论编号。
3. **数字：** 从文本里抽出所有数字（含百分比、dB、Hz、kHz、ppm、秒、阶次），每个都必须等于**该句所引用条目**的某个显示值（允许 `1000 Hz` 与 `1 kHz` 这类单位换算）。文本里不允许出现材料包以外的数字。
4. **结论一致：** 结论段提到的故障类型（削波 / 谐波失真 / 无故障 / 无法判定，中英文词表）必须与引用的结论一致；不得把“无法判定”说成“没有问题”，也不得在不支持某故障时声称有该故障。
5. **下一步：** 每个 `step_id` 都在菜单里，并且引用了菜单给出的触发判定。
6. **措辞禁区：** 不得出现“标准”“合格 / 不合格”“符合 IEC / AES”“industry standard”“SLA”等字样；提到阈值时必须带“演示”。不得给出新的阈值、指标或数值结论。

校验器只读材料包和模型文本，不调用模型；它的每条规则都有离线测试。

## 6. 模板解释（总是可用）

模板解释由代码根据材料包确定性生成，同样分四段，同样带引用，天然通过 §5 的校验。它有三个用途：

- 没有模型凭据时，页面和报告直接显示模板解释；
- 模型输出未通过校验、超时或出错时，改用模板，并在结果里写明原因（`validation_failed:<检查项>`、`timeout`、`provider_error`）；
- 作为离线测试和真实模型评测的对照。

## 7. 产品入口

- **页面：** 情境诊断结果和扫频测试结果下方各加一个“解释”区域。默认显示模板解释；有凭据时显示“用 AI 改写成更易读的说明”按钮（§9 决策 1）。模型解释旁边标明“由 AI 根据本次证据撰写，结论来自确定性引擎”。
- **API：**
  - `POST /api/v1/contextual-runs/{run_id}/explanation`
  - `POST /api/v1/sweep-runs/{run_id}/explanation`
  - 返回解释、来源（`model` 或 `template`）、回退原因、材料包摘要、模型身份（提供方、模型、提示词版本 `v0.3-s1-explain-1.0`）。
- **CLI：** `diagnose contextual ... --explain`、`sweep diagnose ... --explain`。
- **报告：** JSON 和 HTML 报告加 `explanation` 段，带上述身份和来源。
- **凭据：** 沿用 `DEEPSEEK_API_KEY`；没有凭据时只有模板，不报错，也不偷偷换成桩。

## 8. 验证

**离线，进入 CI（不调用模型）：**
- 材料包生成确定，同一次运行得到同一个摘要；
- 模板解释在全部已记录用例（D053 对比报告的 152 例）和扫频合成设备用例上都通过校验；
- 校验器的每条检查都有正反例：编号不存在、数字不一致、单位换算、漏引结论、把无法判定说成无故障、菜单外的下一步、标准类措辞；
- 用脚本化的“假模型”输出驱动服务、API、CLI、页面和报告，覆盖成功和每种回退。

**真实模型评测（交给 Cursor 运行，不进 CI）：**
- 用例：D053 对比报告中的情境诊断用例，加上扫频合成设备用例（含多电平），共约 50 例；
- 自动指标：校验通过率、各类回退原因的分布、结论段覆盖全部结论编号的比例、下一步与菜单一致率；
- 人工评阅：操作员抽查 20 份通过校验的解释，按“读得懂 / 没有说错 / 下一步有用”三项打分；
- 验收线由操作员定（§9 决策 4）。

## 9. 操作员决定

1. **何时调用模型：**
   - A（推荐）：结果页默认显示模板解释；用户点按钮才调用模型改写。成本可控，失败不影响结果。
   - B：每次运行结束都自动调用模型。
2. **下一步建议：**
   - A（推荐）：只能从确定性菜单（§4）里选，模型只负责措辞。
   - B：模型自由写下一步，只要求引用编号。
3. **范围：**
   - A（推荐）：情境诊断和扫频测试一起做，共用材料包、校验器和模板。
   - B：先只做情境诊断，扫频以后再加。
4. **真实模型验收：**
   - A（推荐）：Cursor 跑约 50 例；校验通过率 ≥ 90%，人工抽查 20 份中“说错”为 0，才把模型解释按钮设为默认可见；未达标时按钮隐藏，只保留模板。
   - B：先上线按钮，评测结果作为参考，不设门槛。
