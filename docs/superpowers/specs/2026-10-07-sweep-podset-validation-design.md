# D054 附录：用 pOD-set 公开数据验证扫频测试（设计）

日期：2026-10-07
状态：已批准（操作员 2026-10-07，§8 四项均选 A；D056）。§5 验收标准自本次提交起固定，跑完整数据前不再改动。
上位依据：D054（第 2 阶段扫频测试，决策 4A：真实数据作为附录单独验证）、D052、AGENTS.md。

## 1. 要解决什么

扫频测试（§29）目前只在合成设备上验证过。合成设备的“正确答案”是我们自己设定的，无法说明真实设备上的表现。准备这次验证时，已经发现并修正了一个只在真实设备类型（频响随频率变化）上才会暴露的错误（`sweep-analysis-1.1`）。这说明真实数据验证是必要的。

## 2. 数据：pOD-set

- 来源：Dal Rì、Stefani、Turchet、Conci，“Parametric Overdrive pedal dataset (pOD-set)”，Zenodo，DOI 10.5281/zenodo.15389653，DAFx25 论文配套。
- 许可：**CC BY-NC 4.0**（署名、非商业）。本验证属于非商业研究；仓库里只放派生的数字结果和署名，不放任何音频。若产品今后商业化，需要重新确认这份验证报告的使用方式。
- 内容：27 款模拟过载效果器，每款增益 × 音色各 6 档，共 36 种设置。每种设置有 3 段扫频录音：
  - `s0` / `s1` / `s2`：峰值分别约为 −4 / −10 / −22 dBFS（数据说明写的是 −6 / −12 / −24 dBFS）；
  - 每段 4 秒，48 kHz，24 位；
  - 另有 `n_` 文件，记录噪声底。
- 原始扫频随数据提供（`0_input.zip` 里的 `s0/s1/s2_0-input.wav`）。实测为指数扫频，约 5 Hz 到 24 kHz，L ≈ 0.472 秒（每 0.5 秒频率乘 2.887）。数据说明写的“15 Hz”是名义值。
- 注意事项：
  - 输出录音经过了归一化（数据集附有归一化记录），所以只能比较比值（THD），不能比较绝对电平；
  - 这批扫频不是我们的同步扫频，起止没有静音，文件长度只有 4 秒。

## 3. 原型结果（已做，仅 King of Tone 一款，tone = 3）

用数据集自带的原始扫频做反卷积（估计 L、按 n·f 读取谐波、复用 `sweep-analysis-1.1` 的频段计算），并用合成设备核对方法本身：

| 检查 | 结果 |
|---|---|
| 直通（原始扫频本身） | 各频段 ≤ 0.01% |
| 多项式 x + 0.1x² + 0.05x³，幅度 0.63 | 各频段 3.13–3.14%，理论值 3.14% |

King of Tone 各频段 THD，单位 %：

| 增益 | 电平 | 125 Hz | 250 Hz | 500 Hz | 1 kHz | 2 kHz |
|---|---|---|---|---|---|---|
| 0 | 三档 | ≤ 0.01 | ≤ 0.01 | ≤ 0.02 | ≤ 0.03 | ≤ 0.07 |
| 2 | 三档 | ≤ 0.01 | ≤ 0.01 | ≤ 0.01 | ≤ 0.01 | ≤ 0.02 |
| 5（最大） | −24 | 0.01 | 0.11 | 3.33 | 6.83 | 7.01 |
| 5 | −12 | 0.47 | 6.30 | 10.36 | 10.56 | 8.65 |
| 5 | −6 | 9.41 | 14.42 | 13.62 | 11.31 | 8.57 |

结果在物理上合理：
- 低增益时干净；
- 最大增益时，失真随电平单调上升；
- 失真先出现在中高频，再扩展到低频，符合过载效果器通常先削低频再放大中频的电路结构；
- 以 3 次谐波为主，符合对称削波。

**独立交叉核对（短时频谱）：** 在扫频经过某个频率的时刻，截 20 毫秒做频谱分析，直接测谐波。这种方法不依赖反卷积。

| 频段 | 合成设备（真值 3.14%） | King of Tone 增益 5 |
|---|---|---|
| 1 kHz | 3.22% | 6.83/6.90、10.56/11.06、11.31/11.99 |
| 2 kHz | 3.14% | 7.01/7.11、8.65/8.88、8.57/8.84 |
| 500 Hz | 3.67%（偏高） | — |
| 125 Hz | 6.67%（不可用） | — |

King of Tone 一栏为“反卷积/短时频谱”，三组依次是 −24、−12、−6 dBFS。

短时频谱在低频窗口内的周期太少，偏差大，因此**交叉核对只用于 1 kHz 及以上频段**。

## 4. 做法

1. **数据获取：** 用 HTTP 分段读取（range request）只取需要的文件（每个效果器 zip 约 1.6 GB，但扫频文件每个只有 0.58 MB），存放在仓库外。清单里记录每个文件的 SHA-256。
2. **分析：** 对“已知但非本产品的扫频”做反卷积分析（§8 决策 1）：
   - 用原始扫频估计 L；
   - 按数据集文件长度对齐；
   - 频段计算与 `sweep-analysis-1.1` 完全相同（同一段代码，不复制）；
   - 噪声底取自谐波响应之外的同长度窗口；
   - 不做满刻度判断，因为录音经过了归一化。
3. **判定：** 用现有 `profile_s1_sweep` 的 5% 演示阈值算出每种设置的起始电平。这只是报告内容，不作为验收标准。
4. **输出（入库）：**
   - `docs/evaluations/v0_3/sweep/podset_check_1/` 下的 `manifest.json`（文件、哈希、许可、署名）、`results.json`（逐录音、逐频段的 THD、主要阶次、可测性、交叉核对值）和报告；
   - 生成脚本可以离线重跑；
   - CI 里不下载数据，只测试脚本逻辑（用合成扫频模拟数据集格式）。

## 5. 验收标准（在跑完整数据之前固定，不按结果调整）

真实设备没有“标准答案”，所以用物理规律和独立方法来检验。以下数值在跑完整数据前写死：

1. **合成核对：** 多项式设备在 125 Hz–4 kHz 各频段与理论值相差 ≤ 0.1 个百分点；直通 ≤ 0.05%。
2. **电平单调：** 同一设置、同一频段，−24 → −12 → −6 dBFS 时 THD 不下降（允许 0.2 个百分点或 10% 的回落）。要求 ≥ 95% 的比较满足。
3. **增益单调：** 同一电平、同一频段、音色固定为 3，增益 0 → 10 时 THD 不下降（容差同上）。要求 ≥ 90% 的比较满足。
4. **低增益干净：** 增益 0 时，各频段 THD 的中位数 < 1%。这里只是看分布，不作硬性要求：有些效果器在增益 0 时本身就带失真，报告中逐一列出。
5. **交叉核对：** 1 kHz、2 kHz、4 kHz 频段中，两种方法相差 ≤ max(15%, 0.3 个百分点) 的比例 ≥ 90%（只计双方都可测、THD ≥ 0.5% 的点）。

任何一项不达标，都如实记录。原因可能是方法问题，也可能是数据特性；分析后另开修正，不在本附录里改阈值（§8 决策 4）。

已知偏差说明：King of Tone 已被用来设计这套方法（§3），报告中会单独标出它的结果，并给出去掉它之后的汇总。

## 8. 操作员决定

1. **外部扫频分析放在哪里：**
   - A（推荐）：在 `dsp/sweep.py` 加一个公开函数 `analyze_known_sweep(recording, stimulus, sample_rate)`，与产品共用频段计算代码。以后如果要支持用户上传自己的扫频文件，可以直接复用。
   - B：只放在评估脚本里，产品代码不动。缺点是需要调用 dsp 的内部函数，或者复制一份代码。
2. **数据范围：**
   - A（推荐）：27 款 × 增益 6 档 × 音色固定为 3 × 3 个电平，共 486 段录音，约 280 MB，按需分段下载。
   - B：全部 36 种设置，2916 段录音，约 1.7 GB。
3. **验收标准：**
   - A（推荐）：采用 §5 的五条，跑完整数据前写入合同，不再改动。
   - B：先跑一遍看分布，再定标准。缺点是有“按结果定标准”的嫌疑。
4. **不达标时怎么办：**
   - A（推荐）：如实入库，在报告中分析原因；如需修正方法，另开设计。
   - B：修正后重跑，只入库通过的版本。
