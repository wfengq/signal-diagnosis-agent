# D052 第 4 阶段：测试向导（设计）

日期：2026-10-07
状态：草案，待操作员决定 §9 四项。批准前不实现，不做任何真实模型运行。
上位依据：D052（路线调整）、D047（自由文字理解与确认机制）、D054/D056（扫频测试及 pOD-set 验证）、D055（解释层）、AGENTS.md。

## 1. 要解决什么

现在产品能做三件事：分析一段现成的录音（情境诊断，D053），按扫频测试一台设备（D054），以及用人话解释结果（D055）。但用户要先自己弄明白很多事：

- 该做哪种测试：上传现成录音，还是播放测试信号再录回来；
- 扫频要录几个音量、用哪个采样率；
- 需不需要参考录音，接线和录音设置怎么做。

用户描述问题的方式往往是“我的音箱一开大声就破音”“这个效果器听起来发糊”，不会直接说出这些参数。测试向导要做的，是把这种描述变成一个**具体可执行的测试方案**：先做什么、录什么、怎么接。用户确认后，按方案进入对应的测试页面，相关参数已经预先填好。

**向导不做判断。** 它只决定“做什么测试”，诊断结论仍由确定性引擎和版本化规则给出。

## 2. 方案目录（确定性）

向导只能从一个固定的方案目录里选，不能自己发明测试。目录如下：

| 方案 | 什么时候用 | 产品入口 | 参数 |
|---|---|---|---|
| `sweep_levels` | 能让设备播放测试文件并录回（音箱、功放、效果器、声卡） | 扫频测试（§29） | 采样率 44.1/48 kHz；音量档数 1–3 及标签；接线方式 |
| `existing_recording` | 只有一段现成录音，无法重新测试 | 情境诊断，沿用 D047 的确认流程 | 沿用 D047 的字段：模式、参考文件、标称频率 |
| `paired_reference` | 有同一信号的“正常”录音和“有问题”的录音 | 情境诊断，参考对比模式 | 参考文件 |
| `nominal_tone` | 用户播放的是已知频率的单音 | 情境诊断，标称单音模式 | 标称频率（只能来自用户文字） |

**接线方式**也只能从目录里选，每种对应固定的操作步骤文本：

| 接线方式 | 适用 |
|---|---|
| `line_loopback` | 声卡输出接设备输入，设备输出接声卡输入（效果器、前级、功放的线路输出） |
| `acoustic_mic` | 音箱放音，麦克风录音（受房间和噪声影响，由有效性规则把关） |
| `digital_capture` | 设备本身有 USB 录音或数字输出 |

**音量档的推荐规则**（确定性）：

- 默认录 3 档。最低一档要比平时使用时低，最高一档是用户说“出问题”的那个音量，中间一档在两者之间。
- 用户说“只有大声时才有问题”时，也同样推荐 3 档，这样能找出失真从哪一档开始。
- pOD-set 验证（D056）发现，有 5 款效果器的失真会随音量增大反而下降。因此方案说明里**不写**“失真会随音量单调上升”，只写“找出第一个超过演示阈值的音量”。

## 3. 用户流程

1. **描述：** 在首页“我要测试一台设备”里写一段话，可以附上已有的文件名。
2. **方案草稿：** 产品给出方案卡片，内容包括：
   - 选了哪个方案、为什么选（只引用用户的原话）；
   - 参数：采样率、档数和标签、接线方式、是否需要参考；
   - 操作步骤：从目录里取的固定文本，模型不自由发挥；
   - 缺少的信息：用问题的形式列出，用户可以直接回答或修改。
3. **确认：** 用户逐项确认或修改，沿用 D047 的规则：草稿里的值本身不算确认。
4. **执行：** 进入对应页面，参数预先填好。
   - 扫频：采样率已选好、音量标签已填好，步骤清单显示在页面顶部；
   - 现成录音：进入 D047 的确认流程。
5. **结果与解释：** 与现在相同，出结论和解释（D055）。如果是向导方案发起的测试，结果页会注明“按测试方案 #… 执行”。

## 4. 模型做什么、不做什么

- **输入：** 用户原文、上传文件名、采样率（如果有）。不包含任何音频内容。
- **输出：** 一个 JSON 方案草稿：
  - `plan_id`（必须在目录里）；
  - `parameters`（采样率、档数、标签、接线方式、参考文件、标称频率）；
  - `missing_fields`；
  - `questions`；
  - `rationale_quotes`：从用户原文里摘出的、支持这个选择的原话片段，必须是原文的子串。
- **不做：**
  - 不生成操作步骤文本，步骤来自目录；
  - 不给结论，不预测是否会失真；
  - 不给任何阈值、标准或数值判断。

## 5. 校验（确定性，失败就拒绝）

模型草稿必须全部通过以下检查，否则改用确定性的**问卷**（§6）：

1. **结构：** JSON 能解析，字段齐全，`plan_id` 和接线方式都在目录里。
2. **参数合法：**
   - 采样率只能是 44.1 或 48 kHz；
   - 档数 1–3，标签互不重复，每个 1–64 个字符；
   - 参考文件必须是上传的文件之一，且不能是测试文件。
3. **数字来源：** 参数中的每个数字（标称频率、采样率、档位标签里的数字）必须出现在用户原文或文件元数据里，或者是目录默认值（48 kHz、3 档），并且标明“默认”。沿用 D047 的数字可采纳规则。
4. **引用：** `rationale_quotes` 的每一条都必须是用户原文的子串。
5. **方案前提：**
   - 选了 `paired_reference` 却没有两个文件 → 拒绝；
   - 选了 `nominal_tone` 却没有频率 → 只能作为缺失字段提问，不能编一个；
   - 选了 `sweep_levels` → 原文里不能有“不能重新录”“只有这一段”等否定说法（词表检查）。
6. **措辞禁区：** 与 D055 相同，不出现“标准”“合格”“IEC”等字样，不出现阈值数字。

## 6. 问卷（总是可用）

问卷是确定性的问题树，无需模型凭据：

1. 能让设备播放一个测试文件并把输出录下来吗？
   - 能 → `sweep_levels`，再问接线方式，然后问“出问题的音量大概在哪”。
2. 不能 → 有没有同一信号的正常录音？
   - 有 → `paired_reference`。
   - 没有 → 播放的是已知频率的单音吗？
     - 是 → `nominal_tone`；
     - 否 → `existing_recording`。

问卷有三个用途：

- 没有模型凭据时直接用；
- 模型草稿被拒或调用出错时，改用问卷，并在页面上写明原因；
- 作为真实模型评测的对照。

这里是回退到问卷，不是回退到桩 planner。

## 7. 产品入口

- **页面：**
  - 首页新增“我要测试一台设备”入口：描述框和“生成测试方案”按钮，旁边是“直接用问卷”链接；
  - 方案卡片逐项确认后，进入扫频页或诊断页，参数预填；
  - 扫频页在有方案时，顶部显示步骤清单。
- **API：**
  - `POST /api/v1/test-plans/draft`：输入描述和文件名，返回草稿或问卷起点；
  - `POST /api/v1/test-plans/confirm`：提交确认后的方案，返回预填参数和步骤清单；
  - 方案有确定性编号 `plan_…` 和版本 `test-plan-1.0`。
- **CLI：** `signal-diag guide "描述" [--file a.wav ...]`，打印方案和步骤，交互式确认；`--questionnaire` 直接用问卷。
- **报告：** 由方案发起的扫频或诊断报告，增加 `test_plan` 段，记录方案编号、确认过的参数和来源（模型或问卷）。

## 8. 验证

**离线，进入 CI（不调用模型）：**

- 方案目录、接线步骤、音量推荐规则的确定性测试；
- 校验器每条检查都有正反例：目录外方案、非法采样率、编造的频率、非原文引用、缺两个文件的参考对比、措辞禁区；
- 问卷：问题树每条路径都落到正确方案；
- 脚本化假模型驱动 API、CLI、页面和报告，覆盖成功、各种拒绝和回退；
- 确认流程：草稿里的值不算确认（沿用 D047 的测试方式）；
- 方案到页面预填的映射，包括扫频的采样率和标签。

**真实模型评测（交给 Cursor，不进 CI）：**

- **用例：** 约 40 段中文描述，每段带“正确方案”和关键参数。用例由我们事先写好并入库，覆盖：
  - 四类方案、三种接线；
  - 只说症状不说条件的描述；
  - 有冲突的描述（例如“只有一段录音”同时说“可以重新录”）；
  - 带频率和不带频率的描述；
  - 英文和中英混合的描述各几条。
- **自动指标：**
  - 方案选择准确率；
  - 关键参数准确率；
  - 校验拒绝率及原因分布；
  - 编造数字的次数（必须为 0，由校验器保证）；
  - 不必要提问率：信息已经齐全时仍然提问的比例。
- **验收线**由操作员定（§9 决策 4）。

## 9. 操作员决定

1. **方案目录范围：**
   - A（推荐）：§2 的四个方案、三种接线一起做。向导覆盖产品现有的全部能力。
   - B：只做 `sweep_levels`，现成录音仍走 D047。
2. **模型的角色：**
   - A（推荐）：只从目录里选方案、填参数、提问；步骤文本来自目录；校验失败就回退到问卷。
   - B：模型自由生成操作步骤，只校验数字和措辞。
3. **默认入口：**
   - A（推荐）：问卷默认可用；模型草稿在真实模型评测达标前隐藏，与 D055 4A 相同。
   - B：模型草稿直接上线，理由是用户反正要逐项确认。
4. **真实模型验收：**
   - A（推荐）：Cursor 跑约 40 个用例；方案选择准确率 ≥ 90%，关键参数准确率 ≥ 90%，编造数字为 0，才默认显示模型草稿。
   - B：不设门槛，结果仅供参考。
