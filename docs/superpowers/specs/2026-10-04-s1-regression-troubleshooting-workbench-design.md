## 1. 目标、依据与授权范围

目标用户是能重复运行音频脚本或 DSP 处理链的开发者。首版帮助用户完成一次排障：检查旧版与新版输出、识别值得调查的变化、补一次有区分力的测试，并核查修复结果。

首版用户问题是：本次修改预期保持行为不变，新版输出却出现变化，哪些变化违反已声明的检查规则，下一次应怎样测试？

目标用户、重复使用需求和节省排障时间的收益均为待验证的产品假设。此前调研支持相邻功能已有公开实现，不支持市场空白、付费意愿或本产品优于竞品的结论。

本 spec 记录已确认的产品设计，不修改现行合同。书面 spec 审阅通过后才进入 writing-plans。实施、commit、push、开 PR、merge、seal、RealLLM 调用均不由本文件自动授权。

## 2. 产品范围与替代方案

| 方案 | 用户结果 | 取舍 |
|---|---|---|
| 两份 WAV 差异报告 | 看见指标变化 | 缺少变化是否异常和如何继续排查的语义 |
| 带预期的比较与一次复测 | 判断指定检查项，补测并核查结果 | 本设计采用，兼顾完整任务和有界范围 |
| 自动加载插件、搜索参数并循环修复 | 自动探索处理链 | 宿主、执行安全和搜索预算超出首版范围 |

首版限定在 S1 周期测试信号，以及预期行为不变的回归检查。保留原有单文件诊断入口。新增比较是独立用途，不能把两份任意输出直接作为现有 paired_reference 的干净参考与被测信号。

首期检查复用削波及适用条件内的谐波测量。测量不适用时保留明确的未覆盖项，不为扩大覆盖新增未经定义的测量。

首版不包括：

- 有意改变音色、增加失真、重做 EQ 的预期变化解释。
- 任意语音、音乐、随机效果器或宽域设备故障诊断。
- 自动修复音频、执行用户程序、加载第三方插件或搜索处理参数。
- 自动峰值归一化、重采样、时间拉伸或自动对齐以促成比较。
- 向量数据库、多 Agent、网络知识检索、数据库持久化、账户或公开部署。
- 服务重启后的案例恢复及案例导入恢复执行。

## 3. 用户流程与输入

用户建立案例，提交旧版和新版输出及测试条件。系统完成最低限度的确定性检查，展示逐项结果，并在有适用方案时提供至多一项复测建议。用户手动执行复测或修复，再提交新结果并明确关联到原比较。

| 输入 | 要求 | 语义 |
|---|---|---|
| 旧版输出 WAV | 必填 | 比较基准，不默认无故障 |
| 新版输出 WAV | 必填 | 本次检查对象 |
| 测试条件 | 必填 | 同一激励、参数一致性、版本标识及对应分析范围的声明 |
| 原始测试输入 WAV | 可选 | 核对来源或支持符合既有条件的分析，不自动成为合格参考 |
| 重复运行输出 | 按需补充 | 检查版本内波动，不能用一次重复证明全局确定性 |

测试条件至少区分用户声明与系统可观测事实。系统记录文件哈希、解码结果和分析范围；处理版本、实际使用的激励与参数属于用户声明，除非有另行定义的验证依据。

文件哈希证明所记录字节的一致性，不证明程序实际执行了声明的版本，也不证明两次渲染使用同一输入。上传原始激励可固定声明所指文件，仍不能单独证明执行来源。

使用 nominal 上下文时，需要用户显式提供现行合同要求的激励声明。禁止从文件名、preset 名称或旧输出角色暗中补齐。

## 4. 比较准入、结果与容差

### 4.1 准入

集中在输入边界验证文件格式、字段类型和引用，在确定性规则中判断科学适用性。无效请求与科学上无法比较是不同结果。

首期要求相同采样率、明确的一一对应通道及同长度的对应分析范围。选定范围外的内容不纳入结论。完整文件长度不同时，报告该差异；没有明确对应范围时拒绝比较。

不自动校正电平或时序差异。无法建立范围对应关系时，要求用户按相同测试设置重新导出。首版也不把未实现的对齐检测称为已验证的对齐。

测试条件缺失、存在已知差异或运行波动未解决时，阻断受影响的回归判定。对于已知随机或不可重复处理链，首版仅保留适用测量和范围限制，不作正式回归结论。

准入按指标处理。谐波测量不适用，不妨碍展示有效削波事实；部分结果有效不能自动变成整条处理链通过。

### 4.2 结果语义

| 用户结果 | 条件 | 必须展示 |
|---|---|---|
| 无法比较 | 缺少必要对应条件或该指标不适用 | 原因、缺失条件和受影响项目 |
| 已测得变化，尚不能判定回归 | 测量有效，但容差或判定依据不足 | 双方值、差异、阻断原因 |
| 在指定检查项中发现回归 | 准入满足且违反预先固定的比较规则 | 规则身份、变化方向、证据与适用范围 |
| 指定检查项未发现回归 | 已准入检查项满足其比较规则 | 实际覆盖项和未覆盖项 |

执行失败是独立的运行状态，不属于上述科学判定。失败、取消、超时和证据完整性错误均不得映射为通过或故障仍存在。

案例汇总保留逐项结果和覆盖范围。只要有已确认失败，应展示该失败及其他未完成项目。没有失败但存在必须检查项目被阻断时，不生成整体通过。

单次诊断与版本比较分别展示。例如，两版均存在削波时，即使削波变化在容差内，旧版和新版的削波事实仍须保留。回归通过不等于无故障，更不等于音质更好。

### 4.3 独立的比较规则配置

每条规则绑定指标、单位、适用条件、方向、差值定义、容差和规则版本。区分绝对差、相对差和百分点差。相对差需要显式的有效分母条件；不满足时不得强算或默认为零。

现有 demo profile 的 1% clipping 和 5% THD 是演示诊断阈值，不是行业标准，也不是版本间变化容差。禁止直接挪作回归验收阈值。

本设计不提供未经测量支持的生产容差。实施可以用显式标记的测试专用规则验证判定机械行为，但测试规则不得自动成为产品默认值。

容差启用前需要独立的规则审阅包，记录适用信号、重复运行数据、正常变更、已知回归、测量不确定性处理和误报漏报结果。先用校准材料选择规则，再用未参与选择的案例验证。未完成审阅的指标只能输出描述性变化。

只有至少一个对目标任务有用的检查项完成上述验证，才能宣称具备可判定的回归功能。描述性比较阶段不得宣传为已完成全部产品目标。

## 5. 谐波归因与证据边界

旧版输出的角色不能证明它是干净参考。原始激励文件也须满足对应分析路径的现行资格条件。

保留 D037 的单文件保守边界、D039 的已测未归因事实，以及 v9.11 的诊断门。两个有效 THD 值的变化不能自行解锁 harmonic_distortion supported_fault。

新增比较记录引用双方测量，但不向 StructuredDiagnosis 填入跨运行 claim。单次诊断 claim 仍遵守有效 same-run Evidence 和同跑规则引用要求。

## 6. 案例、记录与生命周期

以下是设计对象，不是对既有 DTO 的原地改名或字段修改。

| 对象 | 责任 | 不变量 |
|---|---|---|
| 排障案例 | 组织目标、测试条件及各轮关联 | 案例组织状态不能改写已完成测量 |
| 输入记录 | 绑定文件哈希、角色、版本和条件声明 | 基准角色不等于质量标签 |
| 测量记录 | 保存输入身份、执行身份、有效测量和局限 | 保留同跑工具及范围来源，不要求伪造 AgentRunResult |
| 比较记录 | 固定双方测量、准入、规则及逐项结果 | 完成后不可覆盖，规则改变需要新记录 |
| 复测建议 | 固定动作、依据、保持条件和区分目的 | 绑定产生建议的比较记录 |
| 复测关联 | 指向建议或修复前记录与新结果 | 用户明确关联，不从文件名猜测 |

比较中的每个来源引用至少包含运行身份和 Evidence ID，并绑定该侧输入及结果身份。相同 Evidence ID 出现在不同运行时不能视为同一来源。

应用边界校验来源存在性、字段和值的一致性、有效性、指标适用性及范围。派生差值由确定性计算产生，记录双方引用和算法身份；不能冒充某一侧原始 Evidence。

报告构建与序列化边界都须拒绝缺失、串侧或被篡改的引用。导出包含检查引用所需的双方证据和身份信息，不只留下无法解析的 ID。哈希是完整性手段，不构成外部真实性认证。

当前会话保存案例组织状态。完成记录不可变，重测追加记录。运行失败保留先前结果，并单独记录失败原因。不能在失败时用先前成功结果冒充本次结果。

首版导出案例 JSON 和可读报告。WAV 不必嵌入报告，但需有输入哈希和明确的取用条件。报告是人工查阅与审计材料，不承诺仅凭报告恢复计算或自动继续运行。

## 7. 复测建议与 planner

### 7.1 最低检查与建议职责

每次比较先完成同一组适用的最低限度确定性检查。Planner 不得跳过必要检查、变更规则、生成数值或改写判定。

最低检查是新的显式比较能力，不是把现有 RealLLMPlanner 产品诊断静默替换为固定流水线。既有诊断入口及身份保持原义。比较测量无需为了复用接口而虚构一次 LLM 诊断。

复测 planner 使用独立输入输出协议与身份，不暗改 v9.11 prompt。它接收紧凑测量、条件、适用性、阻断信息和候选方案，不接收原始波形或完整 FFT 数组。

确定性逻辑先筛选可用方案，planner 在合格方案中选择至多一项，或明确不推荐。Planner 的自由文本不能添加结构化结果没有的故障判断。

### 7.2 首期方案目录

| 方案 | 适用目的 | 约束 |
|---|---|---|
| 补齐测试条件 | 解决具体缺失信息 | 指明缺少哪项；不虚构用户声明 |
| 原条件重复运行 | 观察同版本重复性 | 保持输入与参数，记录运行来源；重复稳定不证明全局确定性 |
| 两版本共同降低输入电平 | 检查差异是否依赖输入电平 | 两边使用一致的新激励和条件；不对输出事后归一化；不据此直接确认代码或硬件根因 |

方案必须记录可执行动作、保持条件、所需上传材料和不同结果能区分的解释。电平变化幅度等数值参数来自另行审阅的方案配置，不能由 planner 随意填写。没有适用配置时，该方案不可选。

本票不执行用户程序，不自动上传材料，不自动运行下一轮。新结果与建议绑定后重新检查准入，不能因它被称为复测而跳过验证。

### 7.3 失败行为

方案不适用、planner 输出无效、缺凭据或调用失败时，保留确定性比较结果并显示建议未生成或不可用。缺凭据不得静默使用 ScriptedPlanner。

新比较接口应分别表达确定性检查状态与建议状态；不能把没有运行 planner 的结果标为 RealLLM 成功。既有诊断接口的 planner_not_configured 行为不由本设计改变。

模型调用需有明确次数、超时、取消和重试预算，具体值在实施计划及合同定义中审阅。额度耗尽停止建议流程，不能继续自动复测。

## 9. 验收

本节 AC 编号只用于本设计追踪，不是已注册的 T-CX ID。实施前须映射到当时可用的 additive 合同和测试定义。

### 9.1 确定性正确性

| 设计要求 | 必须验证的行为 |
|---|---|
| AC01 相同输出 | 在具备有效规则的检查项中不报回归 |
| AC02 容差边界 | 低于、等于和超过边界按已声明的比较关系判定 |
| AC03 已知新增削波 | 规则适用时识别违反项并引用正确双方证据 |
| AC04 两版均有削波 | 保留双方诊断，不把既有异常无依据称为新增 |
| AC05 输入不匹配 | 采样率、通道及范围不匹配不能误通过 |
| AC06 谐波不适用 | 不填零，不生成有效 THD 差或越权归因 |
| AC07 缺少规则 | 有效差异仅作描述，不产生回归通过或失败 |
| AC08 运行不稳定 | 未解决的波动不能被直接归因于版本修改 |
| AC09 修复复测 | 分别识别异常消失与持续，失败运行不能假成功 |
| AC10 部分覆盖 | 单项通过不隐藏必要项目的阻断和未覆盖 |
| AC11 引用完整性 | 缺失、串侧、同 ID 异运行及值被改动均被拒绝 |
| AC12 数值与类型 | 拒绝非有限数值、非法类型和无效相对差分母 |
| AC13 序列化与不可变性 | 导出引用可解析，重测追加记录，旧结果不被改写 |
| AC14 方案准入 | 不适用方案或未批准参数不能由模型输出绕过 |
| AC15 建议失败 | 失败明确展示，已有比较保留，无 Scripted 回退 |
| AC16 既有行为 | 单文件、contextual 归因、D039、V0.2 密封证据和分层继续受保护 |

测试用例须包含可控注入、正常变更及不应报警的反例。可控注入只证明受控条件能力，不等于真实输入质量认证。

### 9.2 Planner 与用户收益

固定策略与 planner 使用相同初始证据、方案目录及复测预算。两者显式标识，Scripted 仅用于测试流程，不能作为 product_agent 计分来源。

评价建议是否适用、实际复测是否区分案例解释、错误建议、复测次数、用户完成时间及模型调用成本。建议模型不能自评为真值。

案例须包含无有效建议、条件不足和复测未解决的情况，不能只挑能成功的案例。失败和未完成案例保留在人口中。先确定评分、人口和资源边界，再查看用于结论的结果。

先用离线案例验证工程行为，再经单独授权测试真实模型及真实用户任务。时间比较采用双方一致的起止边界；用户操作时间与模型执行时间分别记录。

数值通过线、样本数量和模型预算尚未批准。它们是独立评价设计的明确前置工作，不允许在实现时自行填成产品收益结论。

本任务不续写 OQ-019 的正式结论。dev_1 的 formal dominance 未被接受，既有机器枚举不证明本任务 planner 收益。任何新实验不得覆盖既有 seal、oracle 或战役产物。
