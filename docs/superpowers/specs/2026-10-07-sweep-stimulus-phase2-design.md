# D052 第 2 阶段：扫频激励测试（设计）

日期：2026-10-07
状态：已批准（操作员 2026-10-07，§8 四项均选 A；D054）。授权按本设计实现；不授权任何真实模型运行。
上位依据：D052、D053、`docs/superpowers/specs/2026-10-07-route-adjustment-device-testing-design.md` §5 阶段 2、AGENTS.md。

## 1. 要解决什么

现在的产品只能分析“一段现成的录音”，准确性有原理上的上限：

- 合唱、移相这类不失真的处理，会被误当成谐波增长（D051 的 EGFxSet 检查）；
- 削波本身会产生谐波，规则分不清“削波顺带的谐波”和“真正的谐波失真”（D053 的已知局限）；
- 只能回答“有没有失真”，回答不了“在哪个频率、哪个音量开始失真”。

业界测设备的做法（REW、Klippel、SoundCheck）是让设备回放一个已知的扫频信号，再分析录回的结果。这一阶段把这种做法做进产品。

**场景定义随之更新：** 从“这个周期信号为什么失真”扩展为“设备在已知测试激励下的响应为什么失真”。原 S1 的文字在冻结的 V0.2 文档里，不改。

## 2. 原型验证（离线，只用 numpy）

方法：Novak 等人 2015 年的同步扫频法（Synchronized Swept-Sine，JAES 63(10)）。指数扫频的参数经过同步处理，录回信号反卷积后，线性响应和第 2–5 阶谐波响应会落在时间轴上互不重叠的位置，可以分别取出。

用已知特性的合成“设备”做的实验（48 kHz，20 Hz–20 kHz，约 8 秒扫频）：

| 合成设备 | 100 Hz | 500 Hz | 1 kHz | 3 kHz | 说明 |
|---|---|---|---|---|---|
| 直通（无失真） | 0.02% | 0.00% | 0.00% | 0.00% | |
| 多项式 x + 0.1x² + 0.05x³ | 2.47% | 2.50% | 2.50% | 2.50% | 理论值 2.50% |
| 同上，加 23 毫秒延迟和噪声 | 2.51% | 2.50% | 2.50% | 2.50% | 延迟和噪声不影响 |
| 硬削波 ±0.4 | 8.1% | 8.9% | 8.9% | 8.9% | |
| tanh 软削波 | 6.4% | 6.7% | 6.7% | 6.7% | |
| 只在低频段削波 | 19.2% | 10.3% | 2.0% | 0.00% | 能定位到频段 |
| 线性低通（相当于 EQ） | 0.02% | 0.00% | 0.00% | 0.00% | 线性处理不算失真 |
| 合唱类（随时间变化的线性处理） | 0.01% | 0.00% | 0.00% | 0.00% | D051 的误报在原理上消失 |

## 3. 用户流程

1. **下载测试文件：** 产品确定性地生成扫频 WAV（§4.1），可选 48 kHz 或 44.1 kHz。
2. **回放并录回：** 用户让设备播放这个文件，同时录下设备的输出。最好用声卡直接录线路输出；用麦克风对着音箱也可以，但会有房间和噪声的影响，由有效性检查把关。
3. **上传：** 上传录音，并注明用的是哪个测试文件（采样率）和音量档位。一次可以上传 1–3 个不同音量的录音（§8 决策 2）。
4. **结果：**
   - 每个音量下，各频段的谐波失真和失真最大的阶次；
   - 录音里有没有削波，以及削波对应的扫频频率；
   - 跨音量的总结，例如“90% 音量时 200 Hz 以下超过阈值，60% 以下正常”。

## 4. 做法

### 4.1 测试激励（版本化，`sweep-stimulus-1.0`）

- 同步指数扫频，20 Hz–20 kHz，约 8 秒，峰值 −6 dBFS，首尾各 50 毫秒余弦淡入淡出；
- 前面留 0.5 秒静音，用来测噪声底；后面留 1 秒静音，用来接住设备的拖尾；
- 采样率 48 kHz 或 44.1 kHz，24 位 PCM。

生成过程完全确定，同样的参数得到逐字节相同的文件，文件里附带版本号和参数的哈希。

### 4.2 分析（`dsp/sweep.py`，只用 numpy）

1. **对齐：** 录音和已知激励做互相关，找到起点；相关度太低，判为无效。
2. **时钟漂移检查：** 分别对齐录音的开头和结尾两段，估计播放和录音设备的时钟偏差；超过上限，判为无效。
3. **反卷积：** 用同步扫频的解析逆谱反卷积，再按理论时间位置取出线性响应和第 2–5 阶谐波响应，加窗后求各自的频率响应。
4. **按频段计算：** 每个倍频程频段（63 Hz–16 kHz）的 THD 和各阶谐波含量。
5. **噪声底：** 用前 0.5 秒静音估计噪声底。某频段的谐波如果低于噪声底，就标为“无法测量”，不参与判定。
6. **录音中的削波：** 用现有的削波检测找出削波发生的时刻，再按扫频的“时间 → 频率”关系换算成频率。

### 4.3 证据、规则与结论

- **新工具适配器 `tools/sweep.py`：** 把分析结果变成紧凑的 Evidence，例如每个频段的 THD、有效性、削波频段。它不改动冻结的 `tools/service.py` 和 `tools/contracts.py`（T-CX351）。
- **新规则档案 `profile_s1_sweep` 1.0.0-demo：**
  - 每个频段的 THD 上限沿用 5% 的演示值，明确标注不是行业标准；
  - 对齐相关度、时钟漂移、噪声余量都设演示门槛。
- **确定性判定，沿用 D053 的结论结构：**
  - 有效性不满足：无法下结论；
  - 录音中削波的规则不通过：认定削波，并给出频段；
  - 任一可测频段 THD 超过阈值：认定谐波失真，并给出频段和主要阶次；
  - 全部通过：无故障。

  每个结论都引用同一次运行的证据和规则判定。
- **不改动的：** 情境诊断的运行时、`agent/diagnosis.py` 的校验和现有三种模式。扫频测试是并行的独立入口，做法和回归工作台（D042）一样。

### 4.4 产品入口

- **CLI：**
  - `signal-diag sweep stimulus --rate 48000 --out stim.wav` 生成测试文件；
  - `signal-diag sweep diagnose rec.wav [--level 60%] ...` 诊断录音。
- **API：**
  - `GET /api/v1/sweep/stimulus` 下载测试文件；
  - `POST /api/v1/sweep-runs` 上传录音、查询结果。
- **页面：** 新增“扫频测试”区域，包括下载、上传、按频段的失真图（内联 SVG）和结论摘要。
- **报告：** JSON 和 HTML 报告。

## 5. 验证

**离线，进入 CI：**
- **合成设备的真值测试：**
  - 多项式设备的 THD 与理论值相差在 0.1 个百分点以内；
  - 直通、线性 EQ、合唱类处理的 THD 低于 0.1%；
  - 低频段削波只在低频段超标；
  - 硬削波和软削波被认定，削波频段正确；
  - 加延迟、噪声，两种采样率，结果稳定。
- **有效性测试：** 激励不匹配、录音截断、时钟漂移过大、噪声过大，都判为无法下结论。
- **确定性：** 同样输入，结果逐字节相同；测试文件生成也逐字节相同。

**真实数据（可选，见 §8 决策 4）：** 需要找到“已知扫频激励 + 真实设备录音”的公开数据，并先核实许可证。

## 8. 操作员决定（2026-10-07：1A、2A、3A、4A）

1. **实现方式：**
   - A（推荐）：按 Novak 2015 用 numpy 自己实现，不新增依赖。原型已经验证可行。
   - B：引入 `syncsweptsine` 包（MPL-2.0，规模小，维护情况不明）。
2. **一次运行的范围：**
   - A（推荐）：一次可上传 1–3 个不同音量的录音，分别出结果，并总结“从哪个音量开始超标”。这是设备测试最有价值的结论。
   - B：先只做单个录音，多音量以后再加。
3. **测试激励参数：**
   - A（推荐）：§4.1 的固定参数（20 Hz–20 kHz、约 8 秒、−6 dBFS，48/44.1 kHz）。
   - B：允许用户自定义频率范围和时长。
4. **真实数据验证：**
   - A（推荐）：本阶段只用合成设备进 CI；另外寻找有许可证的“扫频 + 真实设备录音”公开数据，找到后作为附录单独验证。
   - B：必须先有真实数据验证才能合并。
