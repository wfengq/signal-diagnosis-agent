# 产品故障时间定位：确定性分段扫描（设计草案）

日期：2026-10-07
状态：草案，待操作员审批。本文件不授权实现，也不授权任何真实模型运行。
上位依据：AGENTS.md（Scope gates）、`docs/CONTRACTS_V0_3_CONTEXTUAL.md` §17、§24.2、§25、§26，D037、D045、D049。

## 1. 为什么做

产品现在只对整个文件下结论：用户知道“有削波”，但不知道削波出现在第几秒、哪个声道。

增量研究的 T2 已经说明，这件事用确定性方法就能做好。基频修复（D049）之后，离线重算 H1 留出集的 24 个 T2 用例，研究里的确定性分段扫描（B2）结果是：

- 结论 24/24 全对；
- 12 个有故障区间的用例全部定位正确；
- 没有无依据的结论。

所以定位不需要 LLM，也不需要新的阈值：复用已经版本化的分段规则即可。

## 2. 目标与非目标

**目标：** 产品的情境诊断运行结束后，报告和页面给出“故障出现在哪里”，例如“削波：左声道 1.00–1.38 s”。每个位置都引用同一次运行中的分段 Evidence 和规则判定。

**非目标：**
- 不改诊断 planner（仍为 v9.11）和它的 prompt；
- 不让 agent 调用扫描，不改 agent 的结论；
- 不新增规则或阈值，不调用模型；
- 不改冻结的 `tools/` 目录和 V0.2 合同；
- 不做 V0.2 旧版单文件运行路径。

## 3. 做法

### 3.1 扫描

新模块 `app/fault_localization.py`，版本号 `product-segment-scan-1.0`。

- **窗口：** 参数与研究 B2 相同，0.25 s 窗口、50% 重叠。
- **声道：** 单声道只扫 mixdown；立体声扫 left、right、mixdown。
- **每个窗口调用两个工具：**
  - `detect_clipping`；
  - `analyze_harmonic_distortion`（只在 §3.3 允许时调用）。
- **工具来源：** 用 D049 的 `GuardedSignalToolService`，与产品诊断一致。
- **判定：** 用 `profile_s1_segment_evidence` 1.0.0（`rules/profiles/s1_segment_evidence_v1.yaml`，阈值为现有演示值）。某窗口的规则 FAIL 即“该窗口支持该故障”，位置取自被引用 Evidence 的 `time_range` 和 `channel`（§24.2）。
- **合并：** 同一故障、同一声道下相邻或重叠的 FAIL 窗口合并成一段区间，并保留每个窗口的 Evidence 和判定编号。

研究中的 B2 代码（`evaluation/agent_increment/segment_baseline.py`）保持不动，产品模块不导入研究代码，各自版本化。

### 3.2 与诊断的关系

扫描在诊断结束后运行，产生自己的 Evidence 和规则判定，不并入 agent 的 Evidence，不改变 agent 的结论或其引用。

报告分两部分展示（见 §6 决策 1）：
- **与诊断一致的位置：** 诊断结论里出现的故障类型，扫描找到的区间。
- **扫描另外发现、诊断未采纳的位置：** 扫描有 FAIL，但诊断没有支持该故障类型（例如诊断为 `inconclusive`）。这部分明确标为“需要复核”，不是结论。

### 3.3 遵守 D037

单文件模式（`single_signal`）下，产品没有参考文件或声明的基频时不认定谐波失真。因此单文件模式只定位削波；THD 窗口不扫，或扫了也不展示为谐波失真位置（见 §6 决策 2）。

声明单音（`nominal_single_tone`）模式下，用声明的基频对每个窗口做谐波分析，可以定位谐波失真。与参考对比（`paired_reference`）模式在本次范围外，只定位削波；参考对齐的分段比较需要另行设计。

### 3.4 输出

快照和 `ContextualDiagnosisReport` 新增可选字段 `fault_localization`（未设置时不序列化，旧报告形状不变），包含：

- `scan_version`、窗口参数、扫描过的声道；
- 合并后的区间列表：故障类型、声道、起止时间、是否与诊断一致，以及引用的 Evidence 和判定编号；
- 扫描用到的分段 Evidence 和规则判定本身（同一次运行内可追溯）。

页面在诊断摘要卡下方加一块“故障位置”；HTML 报告加同名一节；CLI 文本输出加对应行。

### 3.5 代价

一个 30 秒的立体声文件约 240 个窗口 × 3 个声道 × 2 个工具，约 1,400 次确定性 DSP 调用。实现时实测耗时；如果超过诊断本身的耗时，就只扫 mixdown，再对有 FAIL 的窗口补扫左右声道。

## 6. 待操作员决定

1. **扫描结果与诊断不一致时：**
   - A（推荐）：展示，但标为“扫描另外发现，诊断未采纳，需要复核”。不隐藏信息，也不当成结论。
   - B：只展示与诊断一致的位置。
2. **单文件模式下的谐波：**
   - A（推荐）：不扫 THD 窗口，只定位削波，完全遵守 D037。
   - B：扫描但只作为“观测”展示，不叫谐波失真。
3. **适用范围：**
   - A（推荐）：只在情境运行里做（产品默认路径）。
   - B：V0.2 旧版单文件运行也做。
