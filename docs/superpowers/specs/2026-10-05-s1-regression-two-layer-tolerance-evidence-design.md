## 2. 用户问题与两层模型

用户问题：我看到旧版与新版的削波比例有差值，但不知道这个差值是否大于测量方法的分辨能力，也不知道是否大于我这条处理链自己的抖动。

今天的产品只能给出双侧值和差值（`descriptive_only`）。`repeatability` 是用户声明；`repeat` 关联只是链接，没有任何计算产出。

|  | 第一层：方法灵敏度下限 | 第二层：案例观测波动 |
| --- | --- | --- |
| 回答的问题 | 这个测量方法分辨不了多小的差值 | 这条链在这组条件下，同版本重复运行会抖多少 |
| 证据来源 | 离线可控输入表征，与用户处理链无关 | 用户在本案例内提交的重复运行 |
| 作用域 | 绑定测量算法与配置身份，随产品发布 | 只属于该案例与该组条件，不跨案例复用 |
| 批准方式 | 规则审阅包 + 操作员批准 | 无需逐案例批准；形成规则本身需批准 |
| 缺失时 | 该指标保持 `descriptive_only` | 该指标保持 `descriptive_only` |

判定前提：两层都具备，且所有条件声明允许比较。按现行 §22 阻断规则，这在本切片内只覆盖“声明为确定性、且观测也一致”的案例。任一层缺失，系统不产生“回归”或“未回归”。

两层如何合成为一条判定边界，是数值规则，本文不定。本文只约束一点：合成结果不得比任何一层单独给出的下限更宽松地报回归；第二层观测波动为 0 时，边界至少等于第一层方法下限。

不在范围：有意改变行为的版本、随机或不可重复处理链的正式判定、观测到抖动的链的判定（只展示两层事实）、THD 波动汇总、非周期信号、自动执行用户程序、跨会话保存。

## 3. 第一层：方法灵敏度下限

第一层是一个按测量配置身份绑定的、经审阅的量：低于它的 `clipping_ratio` 差值，产品不得当作可解释的变化。

它不是“可接受的回归幅度”，也不是质量标准。它只说明测量方法在与版本无关的扰动下自己会变多少。demo 诊断阈值（1% clipping / 5% THD）不得作为来源或参照。

### 3.1 表征要回答的扰动

每一项扰动都是“版本没变、测量值却可能变”的来源。清单是候选，审阅时可增删，但删除须写理由。

| 扰动 | 要观察的问题 |
| --- | --- |
| 分析范围起止偏移若干样本 | 边界处的削波段被计入或漏掉时，比例变化多大 |
| 分析范围长度变化 | 分母变化对比例的粒度影响；短范围下一样本的权重 |
| 输入相位与周期非整数倒数 | 同一激励不同起始相位时，顶部样本数是否跳变 |
| PCM 位深与量化 | 16/24/32 位导出对接近满刻度样本判定的影响 |
| 电平极接近满刻度 | 刚好触顶与未触顶之间的跳变性 |
| 叠加低电平噪声 | 噪声把样本推过或拉回判定点的概率 |
| 工具参数快照不同 | 不属于扰动：参数不同时现有规则已拒绝比较，表征按配置身份分别进行 |

### 3.2 材料划分

- 校准材料用于选择下限的形式和候选值；验证材料不参与选择，只用于检验。
- 同一激励及其变体、同一生成参数族必须落在同一组，不得改文件名就跨组。
- 材料清单在查看验证结果前固定，包括拟拒绝比较的输入。
- 可控注入只证明受控条件下的能力，不等于真实输入的质量认证。

### 3.3 审阅包必须包含

1. 适用信号族、通道、分析范围前提，以及明确的不适用条件。
2. 测量算法与配置身份、指标单位（`clipping_ratio` 是比例，不是百分数）。
3. 每项扰动下的实测分布，而非只给一个汇总数。
4. 下限的形式依据：绝对差还是随范围长度变化的量。若证据显示下限强依赖范围长度，则不能批准单一常数。
5. 误报、漏报、拒绝比较和覆盖率的分母；困难案例不得从分母中剔除。
6. 未达标时的退出条款：该指标继续 `descriptive_only`，不缩小人口来凑通过。

数值由离线测量产生并经审阅，不得由 LLM 生成。

## 4. 第二层：案例观测波动

第二层把用户已提交的同版本重复运行，确定性地汇总成一条“观测波动”事实；它是测量事实，不是判定。

### 4.1 什么算一次重复运行

一次重复运行指：同一案例内、用户以 `repeat` 关联明确指向某条比较记录的新提交，并且满足全部条件：

- 同一侧的版本声明与父记录一致。
- `stimulus_key`、`parameters_key` 与父记录一致。
- 采样率、通道、分析范围、工具参数快照与父记录一致。
- 该侧测量有效。

不满足任一条的提交仍作为普通比较记录保留，但不进入波动计算，并显示被排除的原因。系统不从文件名、时间或相似度猜测哪些提交是重复。

### 4.2 波动事实的内容

按侧（baseline / candidate）分别形成；首期只有 clipping\_ratio 一项指标。每条事实至少记录：

- 参与计算的每次运行的来源引用（运行身份、输入哈希、bundle 摘要、Evidence ID）。
- 每次运行的原始值，而非只留汇总。
- 运行次数，以及被排除的提交及原因。
- 汇总量及其算法身份。汇总量的具体形式（极差或其它）待审阅确定。
- 该事实适用的条件键（激励、参数、范围、通道、配置）。

输入字节完全相同的多次提交（哈希一致）单独标识。它们证明的是字节一致，不证明程序重新运行过；它们计入重复次数，波动事实同时记录其中字节相同的次数，并附固定提示。以上计数规则已被同日后续决定收紧：只有用户明确声明“该文件来自一次独立重新渲染/重新运行”的重复提交才计入次数，声明为否、未知或未声明的只记为重复提交；声明为独立且字节相同的可以计数并照旧标注。该声明系统无法验证。

### 4.3 与用户声明的关系

`ComparisonConditions.repeatability` 保持原字段、原取值、原含义，仍是用户声明。观测波动是新事实，不回写、不覆盖声明。

| 用户声明 | 观测结果 | 系统行为 |
| --- | --- | --- |
| `declared_deterministic` | 重复值完全一致 | 记为观测波动 = 0，与声明并列展示；判定边界仍不低于第一层方法下限；不据此宣称全局确定性 |
| `declared_deterministic` | 重复值不一致 | 展示矛盾；阻断受影响指标的判定，直到用户更新声明或解释 |
| `unknown` | 有足够重复 | 展示观测波动；声明仍为 `unknown`，继续阻断；提示用户可更新声明并新建比较 |
| 任意 | 重复不足 | 显示“重复不足，尚无波动事实”，不填零 |

### 4.4 失效与边界

- 条件键变化（换激励、换参数、换范围、换配置）后，旧的波动事实不适用于新比较，但不删除。
- 只重复了一侧时，另一侧没有波动事实；不得用一侧代替另一侧。
- 重复稳定只说明这几次在这组条件下稳定。
- 失败、取消、测量无效的提交不进入计算，也不从计数中消失。
- 波动事实只存在于当前会话，受现有每案例 16 次提交上限约束；重复运行与正式比较共用这个额度。额度耗尽时显示原因，已有波动事实与比较记录不受影响。

## 5. 对象形状、合同落点与分层

两层都以新增对象表达，不改 §22 既有字段的含义，不动冻结的 V0.2 §§1–64。以下是设计对象，不是接口签名；名称与字段在实施计划中按当时基线确定。

| 设计对象 | 责任 | 所属层 | 不变量 |
| --- | --- | --- | --- |
| 方法灵敏度记录 | 绑定指标、工具、配置身份、适用条件、下限形式与版本 | `rules/` | 只能来自随包发布的经批准配置；客户端不能上传或自称已批准 |
| 重复运行资格判断 | 判定一次提交能否计入某侧的重复 | `rules/` | 纯函数；只读测量记录与条件声明 |
| 观测波动记录 | 按侧、按指标汇总重复运行，持有全部来源引用 | `rules/`（计算）+ `app/`（组织） | 派生量；不冒充任一侧原始 Evidence；完成后不可覆盖 |
| 判定依据引用 | 比较记录指明它用了哪条灵敏度记录、哪条波动记录 | `rules/` | 缺任一引用则状态只能是 `descriptive_only` 或 `not_comparable` |

落点建议（待操作员决定）：

- 合同走新增章节（§22 之后的新节，或 §22 的新增小节），不改写 §22.1–22.6 原文。
- 需要一条新的决策记录和一组新的测试 ID；编号在实施基线上核对空闲后分配。
- 现有 `ComparisonProfile` 与 `ComparisonRule` 是否承载第一层，还是另建对象，由实施计划在核对后提出。设计约束只有一条：不得改变既有字段的含义。

分层与证据纪律沿用现行要求：

- 波动的计算是确定性代码；LLM 不生成、不修改、不解释出新的数值。
- `rules/` 不导入 `app/` 与 `agent/`；`evaluation/` 不导入 `app/`。
- 复测 planner（`v0.3-s1-retest-1.0`）的输入可以增加“是否已有波动事实”的紧凑标志，但这属于协议变更，须起新身份，不在本切片内。
- 诊断路径（v9.11 prompt、因果策略、D037、D039）不受影响；波动事实不进入 `StructuredDiagnosis`。
- 产品 tree 变化时追加代码身份行，不重写旧行。

## 6. 结果语义与展示

四种指标状态的取值不变；变化的只是 `descriptive_only` 下要说清缺哪一层。

| 第一层 | 第二层 | 条件声明 | 指标状态 | 必须展示 |
| --- | --- | --- | --- | --- |
| 无 | 任意 | 任意 | `descriptive_only` | 双侧值、差值、“无已批准的方法下限”；若有波动事实一并展示 |
| 有 | 无或重复不足 | 允许 | `descriptive_only` | 双侧值、差值、差值与方法下限的关系、还差哪一侧的重复 |
| 有 | 有 | 阻断（`no` / 相关 `unknown` / 声明与观测矛盾） | `descriptive_only` | 阻断原因及两层事实 |
| 有 | 有 | 允许 | `regression_detected` 或 `no_regression_detected` | 规则身份、两层引用、变化方向、适用范围、未覆盖项 |
| 任意 | 任意 | 测量无效或输入不匹配 | `not_comparable` | 原因与受影响项 |

展示约束：

- 差值低于方法下限时，文案是“差值在测量方法分辨能力以内”，不是“无回归”。
- 差值在观测波动以内时，文案是“差值不超过已观测到的同版本波动”，并注明重复次数。
- 回归通过不等于无故障。两版均有削波时，双方削波事实仍须保留。
- 案例汇总沿用现规则：必须检查项被阻断时不生成整体通过；执行失败不映射为通过。
- 波动事实在报告中归入“派生量”，与原始 Evidence 分开列出；导出包含校验它所需的全部来源。
- 界面文案使用固定模板，不渲染模型自由文本。

`thd_percent` 在本切片内不进入上表的判定行：基频兼容规则未经审阅，按 §22.3 继续阻断。其重复运行值不汇总为波动事实，只按现状显示每条比较的双侧值。

## 7. 验收要求与反例

以下编号只用于本设计追踪，不是已注册的 T-CX ID。实施前须映射到当时可用的 additive 合同与测试定义。

| 设计要求 | 必须验证的行为 |
| --- | --- |
| TV01 缺层不判定 | 任一层缺失时，有效差值只作描述，不产生通过或失败 |
| TV02 重复资格 | 版本、激励、参数、范围、通道、配置任一不一致的提交不计入波动，并显示原因 |
| TV03 不串侧 | 一侧的重复不能计入另一侧；相同 Evidence ID 出现在不同运行时不视为同一来源 |
| TV04 重复不足 | 次数不足时无波动事实，不填零，不默认为稳定 |
| TV05 单侧重复 | 只重复一侧时，另一侧保持缺失，判定不成立 |
| TV06 声明与观测矛盾 | 声明确定性但观测到差异时，展示矛盾并阻断，不改写声明 |
| TV07 条件变化失效 | 条件键变化后，旧波动事实不被新比较引用，旧记录仍可查 |
| TV08 字节相同的提交 | 只有声明为独立重新渲染的重复才计数；其中哈希一致的照常计数并标注；未声明、声明为否或未知的只记为重复提交，不计数 |
| TV09 失败不污染 | 失败、取消、无效测量不进入计算，不改变已有波动记录，也不从计数中消失 |
| TV10 引用完整性 | 缺失、串侧、值被改动、摘要不符的波动记录在报告构建与解析边界被拒绝 |
| TV11 不可变性 | 新增重复运行产生新的波动记录，旧比较记录及其依据引用不被改写 |
| TV12 客户端不可注入 | 客户端不能上传波动值、方法下限或“已批准”标志来启用判定 |
| TV13 下限绑定身份 | 测量配置身份与灵敏度记录不匹配时，第一层视为缺失 |
| TV14 产品默认不变 | 无已批准配置时，产品构造路径仍为纯描述性；测试夹具配置不被产品构造器加载 |
| TV15 既有行为 | 单文件诊断、contextual 归因、D039、§22 既有记录校验、V0.2 密封证据和分层继续受保护 |

第一层审阅包的验收另计，见 §3.3；它是证据审阅，不是单元测试。

反例必须入测，不能只挑能成立的案例：

- 确定性链：重复结果逐字节相同。
- 轻微不稳定链：重复间差异与版本间差异同量级。
- 两版均有削波且差值很小。
- 旧版无削波、新版有削波。
- 用户把新版输出误标为旧版的重复。
- 分析范围极短，一个样本就明显改变比例。

这些测试证明判定机械行为正确。它们不证明两层容差对用户有用，也不证明任何数值已校准。
